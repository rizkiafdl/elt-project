# Cosmos. The lower bound is 1.15.1 and the reason is a bug, not a preference.
#
# The original pin was >=1.14,<1.15 — "pin to the version that was verified"
# (elt-pipeline-verification.md §4), never a known incompatibility. Phase 2 §10.1
# revisited it deliberately on 2026-09-10 and moved it. The evidence is in
# secondary/elt-pipeline-plan/phase-2-execution-findings.md topic 19; the summary
# is that cosmos.operators.kubernetes.build_kube_args behaves differently at each
# of the three releases:
#
#   1.14.2  never sets `cmds`. The executable travels inside `arguments`, so a pod
#           built from an image whose ENTRYPOINT is already ["dbt"] runs
#           `dbt dbt run --select ...` and dbt exits on an unknown subcommand.
#   1.15.0  forces cmds = ["dbt"] for EVERY image and ignores what the caller asked
#           for. Correct for this image by accident, wrong for anyone else's.
#   1.15.1  preserves a caller-supplied `cmds` and strips the leading executable
#           only when cmds == ["dbt"]. This is the only release that is correct
#           for BOTH image shapes, and the only one that lets §10.3 state the
#           entrypoint explicitly instead of relying on a default.
#
# ⚠️ THE BUMP ALONE DOES NOT FIX THE POD COMMAND. It makes the fix expressible.
# §10.3 must still pass cmds=["dbt"] in operator_args. 1.15.1 with no cmds behaves
# like 1.14.2 and produces `dbt dbt run` again.
#
# The API diff between 1.14.2 and 1.15.1 was checked field-by-field on the
# ProjectConfig / RenderConfig / ExecutionConfig dataclasses and is ADDITIVE ONLY —
# nothing this project passes was removed or renamed.
#
# ⚠️ astronomer-cosmos is NOT in the Airflow constraints file this image builds
# against, so this line is the only thing deciding the version. Nothing downstream
# will correct a mistake here.
astronomer-cosmos[kubernetes]>=1.15.1,<1.16
